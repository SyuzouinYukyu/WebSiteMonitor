# WebSite Monitor v1.1.6

## v1.1.6 の変更

連続エラー警告回数をアプリ全体設定へ追加しました（既定3、0で無効、1～9999）。DB保存済みの連続エラー数が閾値と一致した時だけサイトごとに1回警告し、正常取得後の新しい連続障害で再度警告します。更新通知OFFでも有効です。バージョン情報にGitHub URLを追加しました。DB schema 7 / wsmcfg形式1を維持し、旧設定の新項目省略時は3を使用します。

## v1.1.5 の貼り付け操作

サイトの追加・編集画面の「監視方式の詳細」に、RSS / Atom URL、CSSセレクター、XPath、正規表現の入力欄と連動する「貼り付け」ボタンを追加しました。RSS / Atom URLは既存のURL正規化を使用します。式は構文を維持し、末尾のCR/LFだけを除去します。自動・ページ全体・テキストでは詳細入力欄とボタンを表示しません。監視・通知・DBスキーマ7・設定形式1には変更ありません。

実機GUIで4方式の表示切替・貼り付け・監視テスト・保存後の再編集を確認済みです。自動テストは337件成功、失敗0、スキップ0です。

## v1.1.4 の再起動修正

旧プロセスの終了と識別情報の取得が競合する経路を修正しました。補助プロセスは同じOSハンドルでPID・起動時刻・実行パスを確認し、旧プロセスへ準備完了を通知します。旧プロセスが引き継ぎを承認した後に終了を待ち、その補助プロセス自身が通常起動へ進みます。準備確認は最大10秒、旧プロセスの終了待機は従来どおり最大30秒です。確認失敗では強制終了・自動的な通常起動をせず、中止を表示します。メインとトレイは同じ経路で、確認中や終了中の重複要求を抑止します。

監視・通信の排出、通知音の終了、設定保存は補助プロセスを開始する前に完了させます。引き継ぎ後にトレイ・フォーム・リソースを解放し、旧プロセスが完全終了してから新インスタンスがMutexを取得します。この順序は、保存・排出失敗時に再起動待機プロセスを作らないために維持しています。

SQLiteスキーマ7、設定形式1、暗号・DPAPI・FIFO・v1.1.3の5機能に仕様変更はありません。検証判定は「一部未完了」です。最終EXEの代替検証はトレイ経路20回・メイン経路5回に成功しましたが、物理GUI操作は未実施です。詳細は [RELEASE_VERIFICATION.md](RELEASE_VERIFICATION.md) を確認してください。自動プローブを実際のトレイクリックと同一視しないでください。

## v1.1.3 の変更と操作

- サイト追加・編集と設定は、入力本文だけを縦スクロールし、保存／キャンセルを固定した下部に表示します。設定の「バージョン情報 / 第三者ライセンス」も下部に残ります。実際のDPI適用後のウィンドウ外枠を、タスクバーを除いた現在のモニターの作業領域へ収めます。小さい作業領域では縮小でき、再サイズ・モニター移動・DPI変更時に再調整します。
- 更新ダイアログ右下の「Webサイトを見る」は、既存の安全な通知先URLをWindowsの既定ブラウザーで開きます。リンクと同様、閲覧だけでは確認済みにしません。「閉じる」、×、Escで現在表示中の1件だけを確認済みにして閉じ、残りがあればFIFO順に次を表示します。Enterはフォーカス中のボタンの標準操作です。「Webサイトを見る」上では閲覧だけを行い、「閉じる」上では確認して閉じます。確認保存が失敗すると開いたまま再操作できます。アプリ全体の終了やWindows終了では未確認通知を残します。
- 「設定入出力」の4項目と各メニューへ共通フォントを一度だけ適用します。継承済みサイズの再拡大を防ぎ、繰り返し開く／倍率を変更しても親コマンドと同じ字体・サイズ・スタイルになります。
- ツールバーの「更新履歴」と「設定」の間に「ログ」を追加しました。実際に使用中のdata保存先のlogs直下で、更新日時UTCが最新の `.log`（大文字拡張子も可）をWindowsの関連付けで開きます。同日時はファイル名の昇順です。内容の読み込み、生成、書き換え、関連付け変更は行いません。圧縮ログ、別拡張子、サブフォルダー、リンクファイルは選びません。対象なし／起動失敗は機密情報を含まない固定日本語メッセージで案内します。
- SQLiteスキーマ7、wsmcfg形式1、暗号化・DPAPI・監視判定・通知FIFO・音声方式は変更していません。v1.1.2のソースとEXEを唯一の基準とし、旧版、data、正式画像、アーカイブ、GitHub Release・タグには変更を加えていません。
- 検証の範囲と未検証事項は `RELEASE_VERIFICATION.md` を参照してください。自動レイアウト検査は、物理操作・全DPIでの目視確認・ブラウザーやログの関連付け先の実操作と同じ意味ではありません。

## v1.1.2で追加した機能（継続）

- メイン画面のタイトルとトレイ表示は実際の製品バージョンを示します。配布ファイル名は `WebSiteMonitor_v1.1.6.exe` です。
- ツールバーの「更新履歴」は必ず「すべて」から開きます。右クリックの「更新履歴」は選択サイトから開きます。上部の「表示対象」で即座に切り替えます。各対象の最新1,000件をSQLで取得し、無効サイトも選択できます。同名サイトは安全なURLとIDで区別します。履歴表示は通知の確認やデータの書き換えを行いません。
- 一覧を並べ替えた後の編集・削除・確認・ブラウザー表示などは固定サイトIDで解決します。削除済みサイトへの操作は中止します。再読み込みは並べ替え・選択ID・列幅を維持します。
- フォント操作は `Ctrl + +` / `Ctrl + -`（テンキーも可、プラスはShift併用可）です。10～18pt、1pt刻みで保存し、全画面に適用します。通常ホイールとCtrl＋ホイールはフォントを変更しません。
- 秘匿済み代替表示と通信診断を表示時に日本語化します。Web本文・サイト名の英語を翻訳しません。既存の秘匿判定・基準ハッシュ・保存履歴は変更しません。
- 実際の変更をSQLiteへコミットした時だけ、ローカル日時・サイト名・監視URLを「更新検知」として一行に記録します。通知OFFでも記録します。未知の秘密パスも保護するためURLは保守的に公開オリジンのみとし、認証情報・パス・クエリ・フラグメントを出しません。一般ログの秘匿は従来どおりです。
- 右端の「再起動」「完全に閉じる」は、共通の停止・完了待機・保存処理を使用します。「完全に閉じる」は再起動せずプロセスとトレイを終了します。編集画面は先に保存／キャンセルして閉じてください。設定入出力中は終了を受け付けません。通常のメイン画面の×はウィンドウだけを閉じ、監視はトレイに残ります。
- schema 7、wsmcfg形式1、暗号化条件、DPAPI記憶、通知FIFO、新規音量100・更新ダイアログON、外部PATHのFFmpegのみという方針は維持します。

### v1.1.2等からの手動移行

旧版と新版を完全に終了してから、必要な場合に限り利用者自身で旧版の `data` フォルダーを新版EXEと同じ場所へ複製してください。自動移動・旧版の書き換えは行いません。schema 7からのスキーマ移行はありません。同じWindowsユーザー・同じPCならDPAPIの記憶も利用できます。別PCへ設定を移す場合は暗号化wsmcfgと既知のパスワードを使用してください。履歴・未確認通知はwsmcfgには含まれません。

## v1.1.1 の変更

- 初回エクスポート成功後、パスワードをWindows DPAPI（CurrentUser）で保護し、`data/local/export-password.dpapi`へ原子的に記憶します。同じWindowsユーザーでは再起動後も再入力を省略します。破損・復号不能の場合は再入力へ戻り、保存失敗でも成功したバックアップは維持して警告します。
- メイン画面「設定入出力」またはトレイの「エクスポート用パスワードを変更」「記憶したパスワードを解除」で管理します。変更失敗時は旧情報を保持し、解除には確認が必要です。インポートは毎回入力し、記憶情報を使用・変更しません。
- DPAPIはWindowsユーザーに紐づきます。環境・アカウントを変更すると再入力が必要になる場合があります。同じWindowsアカウントを利用できる第三者からは保護できません。パスワードは平文保存・ログ記録せず、記憶情報はsettings.json・SQLite・wsmcfgへ含めません。バックアップを復元する際は作成時のパスワードが必要です。変更や解除は過去のバックアップへ遡及しません。忘れたパスワードは復旧できません。
- サイト編集の監視テスト中はボタンが「中止」になります。再クリックでHTTP取得・本文読み込み・再試行待機をキャンセルします。閉じる場合もキャンセルし、処理終了後に操作へ復帰します。
- HTTPの1試行30秒、手動テスト全体45秒、通常監視全体100秒を上限とし、本文停止も対象です。最大2回の再試行・16MB制限等は維持します。Retry-Afterが残り期限を超える場合は早期の再試行を行わず失敗します。タイムアウト・中止は更新通知を発生させず、前回の基準値・履歴を保持します。
- メイン画面またはトレイの「再起動」で完全再起動します。未保存の編集画面は先に保存またはキャンセルして閉じてください。設定入出力中は再起動できません。処理停止・保存・リソース終了後、同じEXEの内部補助モードが旧PIDと開始時刻を確認し、完全終了を最大30秒待って通常起動します。終了確認に失敗すると二重起動を強行しません。
- ページ全体のプレビューはHTMLの表示テキストを秘匿してから短縮します。監視対象の原文・ハッシュ計算は変更しません。巨大HTMLの属性・スクリプトをプレビューへ出さず、壊れた引用符等は引き続きフェイルクローズにします。安全な処理段階と受信バイト数を表示します。
- SQLiteスキーマ7、wsmcfg形式1、既存設定、新規音量100・更新ダイアログON、外部PATHのFFmpegのみ使用する方針を維持します。旧版ソース・EXE・GitHub Release/タグは変更しません。

## v1.1.0 の変更・利用条件

- Windows 11 x64 / .NET 10 self-contained・single-file。利用者による.NETランタイム導入は不要です。
- FFmpeg実行ファイル・DLL・ZIPを本体・公開ソースへ一切同梱しません。自動取得・インストールもしません。
- 圧縮音声等の通知音には外部FFmpegが必要です。利用者が https://ffmpeg.org/download.html から取得し、ffmpeg.exeのフォルダーをPATHへ登録してください。引用符付き・空白・日本語を含む絶対パスにも対応します。相対パスやカレントディレクトリは探索しません。
- `ffmpeg -version` で導入を確認し、PATH変更後はWebSite Monitorを再起動してください。未導入なら音声再生だけが明確な案内付きで失敗し、監視・他通知・FIFOは継続します。PCMとMIDIの既存方式は維持します。対応形式は導入したFFmpegビルドに依存し、DRMを解除しません。
- 新規サイトは音量100・更新ダイアログON。保存済みの値は変更しません。旧スキーマ移行時の更新ダイアログOFFも維持します。SQLiteスキーマ7のままです。
- 以下の旧版変更履歴にある「内蔵FFmpeg」「展開cache」は過去の仕様であり、v1.1.0には適用されません。

## 設定のエクスポート・インポート

メイン画面の「設定入出力」またはトレイから「設定をエクスポート」「設定をインポート」を選択します。標準ファイルダイアログで単一の `.wsmcfg` を扱い、既定の名前は `WebSiteMonitor_Settings_YYYY-MM-DD.wsmcfg` です。パスワードは8文字以上、初回の書き出し時は確認入力が必要です。v1.1.1では成功後にDPAPIで記憶します（上記参照）。インポート時は毎回入力します。紛失したパスワードは復旧できません。

形式1のUTF-8 JSONをAES-256-GCMで暗号化します。PBKDF2-HMAC-SHA256 200,000回、ランダムSalt16bytes、Nonce12bytes、Tag16bytesを使用し、ヘッダーも認証します。識別子WSMCFG01、独立した形式番号1、反復数、Salt、Nonce、データ長、Tag、暗号文から成ります。暗号化前の一時書き出しファイルは作りません。暗号化ファイルは原子的に保存します。認証・全必須項目・設定値・形式を検証してから反映し、読込拒否では既存データを変更しません。

サイトの全ユーザー設定（URLに含む認証情報、Feed URL、抽出条件、User-Agent、スケジュール、通知、音量、音源パス）とアプリ全体の全設定（フォント、ウィンドウ位置・寸法、列幅、自動起動、Windows統合、通知、保持期間、PCM設定）を対象にします。内部ID・監視世代・取得状態・自動検出Feed・本文/ハッシュ・履歴・未確認通知・ログ・キャッシュは含めません。音源はパスだけで、音声データは含めません。通常のポータブルDBとsettings.jsonは従来どおりローカル保存です。公開や共有には暗号化したwsmcfgだけを使い、パスワードは別経路で伝えてください。

- 初期選択「追加・統合」：現在のサイトを維持し、未登録定義を追加します。同一のURL・方式・Feed URL・CSS・XPath・正規表現・User-Agent設定は既存IDへユーザー設定だけを反映し、履歴・FIFO・取得状態を維持します。繰り返し取り込んでも増殖しません。既存の重複定義がある場合は最小IDへ反映し、既存重複を自動削除しません。ファイル内の同一定義は順に反映され、後の設定が優先されます。
- 「置換」：別途確認したうえで取り込み元のサイト構成へ置換します。同一定義のID・履歴・FIFOは維持します。削除対象に履歴または未確認通知がある場合は全体を中止するため「追加・統合」を選んでください。
- 両方式ともアプリ全体の設定は取り込み元へ置換します。確認画面に自動起動・Windows統合・表示・通知も対象と明示します。監視と表示へ直ちに反映します。見つからない絶対パスの音源は件数だけを警告し、取り込みと監視は継続します。

取り込みでは新規監視の開始を止め、進行中の監視を最大20秒待ちます。編集画面が開いている間は開始できません。入出力中は二重実行・編集・終了・フォント操作を抑止し、監視完了イベントは遅延処理します。暗号化・復号・反映はバックグラウンドで行います。SQLiteトランザクションと原子的settings.json更新を連動させ、失敗時はDBをロールバックし、メモリ内に保護した元の設定ファイルをバイト単位で復元します。プロセス強制終了や媒体故障に対する分散トランザクション保証はありません。復元自体が失敗した場合は、その旨を明示します。

## v1.0.9 の変更

- JSONの引用符・改行、パーセントエンコードされた秘密キーを、キー分解・デコード・秘密判定の順で秘匿します。診断入力は65,536文字、キーは8,192文字、デコードは3段階が上限で、解析失敗時は原文を返しません。
- 外部例外は固定のエラー種別・HTTP状態・秘匿表示だけへ要約し、未知の個人情報や秘密値が自由文として残らないようにしました。結果、SQLite `LastError`、ログとFeedフォールバックの診断で共通処理を使用します。
- SQLiteスキーマ7、監視URL・認証付き取得、通知・FIFO・UI・音声の仕様は維持しています。

## v1.0.8 の変更

- 例外メッセージの途中に現れる秘密パラメーターを先に検出・秘匿し、`CheckResult.Message`、SQLiteの`LastError`、新規ログのいずれにも保存・表示しないようにしました。
- 既存のURL・Bearer資格情報・通常キーの秘匿処理は維持し、スキーマ7および既存データの形式は変更していません。

## v1.0.7 の変更

- Windows通知、独自ポップアップ、更新ダイアログ、履歴、一覧のURL表示・起動を共通の安全な通知先に統一しました。履歴にもイベント発生時の安全なURLを保存します。
- 認証キーの派生名・区切り変種・最大3段階のエンコードを検査し、不正・過剰な入力はルートURLへの代替またはリンク無効化で扱います。公開URLの正常なクエリ・フラグメントは保持します。
- RSS/Atomには項目別の更新前状態がないため、最初の記事リンクを更新対象と推測しません。明示通知先または安全なサイトURLを使用し、更新検出自体は維持します。
- ログの共通出力境界でURL・既知の認証値を伏せ、ログ書き込み失敗でも監視を継続します。履歴とエラー表示も読み取り時に再検証します。

履歴ごとの通知先を保持するため、スキーマ6から7への変更はHistoryの通知先URL列1個だけです。移行前にSQLiteオンラインバックアップを作成し、既存の履歴・未確認通知・順序・通知設定を保持します。RSS項目比較用の保存形式や外部取得は追加していません。

過去のログ、履歴プレビュー、旧未確認通知、移行前バックアップには旧版が保存した認証値が残り得ます。原本を自動で書き換え・削除することはありません。過去に漏洩した可能性があるトークンは発行元で失効・再発行してください。確認はローカル環境で行い、原本を外部へ送らないでください。不要な旧ログを削除する場合はアプリを終了し、必要な診断情報を伏せて保管したうえで、該当ファイルだけを削除してください。履歴DB内の旧記録を手動整理する場合は、事前バックアップを取り、監視URL設定・履歴ID・未確認状態を保持してください。

## v1.0.6 の変更

- 更新通知の抑止判定と未確認通知の保存を同じトランザクションで一致させました。
- サイト別の「通知先URL（省略可）」を追加しました。認証付きフィードでは、秘密情報を含まない公開ページを指定してください。
- 通常ページの無害なクエリやフラグメントを保持し、秘密情報を疑うURLはオリジンのルートへ置き換えます。旧版の未確認通知も表示と起動の直前に再検証します。

v1.0.5のDBからの移行前には、SQLiteオンラインバックアップを同じdataディレクトリに `WebSiteMonitor.db.pre-v1.0.6-日時-識別子.bak` として作成します。移行後のDBはスキーマ6です。既存の未確認通知と履歴は保持します。旧版へ戻す際はアプリを終了し、移行前のバックアップを復元してください。移行後の変更はバックアップには含まれません。

Windows 11 x64 向けの軽量なポータブル Web サイト更新監視ツールです。タスクトレイ常駐と one-shot scheduler を使い、RSS 2.0 / Atom、自動 Feed 検出、ページ全体、本文テキスト、CSS Selector、XPath、正規表現を監視します。ETag / Last-Modified、SQLite履歴、Windows通知、独自ポップアップ、通知音、単一インスタンス、自動起動を備えています。

## v1.0.5 の変更

- 通知方式に既定OFFの「更新ダイアログ」を追加しました。Windows通知・独自ポップアップ・更新ダイアログ・通知サウンドを独立して選べます。
- 更新時に未確認通知をSQLiteへ履歴と同時に保存し、FIFO順で最大1個を非モーダル表示します。v1.1.3では「閉じる」・×・Esc（Enterはフォーカス中のボタンに従う）の確認保存が成功するまで維持し、リンク・閲覧・フォーカス喪失では確認済みにしません。通知設定OFFやサイト削除後も既に発生した未確認通知を保持します。
- アプリ終了・OS終了では確認せず、次回起動時に復元します。確認保存に失敗した場合はダイアログを維持し、DBへの更新保存に失敗した場合は更新と履歴もロールバックして次の巡回で再検出します。
- 更新ダイアログのURLは認証情報・クエリ・フラグメントを除去します。RSS/AtomではサイトURLと同じオリジンの通常ページリンクを優先します。リンクを開いてもダイアログは閉じません。
- 表示名を「WebSite Monitor」に統一しました。プロジェクト・名前空間・DBファイル名・通知ID・自動起動識別子は互換性のため維持します。

## v1.0.4 の要点

- 必要なサイトだけ「ブラウザー互換User-Agentを使用する」を ON にできます。既存サイトは OFF のままです。UAを切り替えると旧取得結果・ETag・Last-Modified・baselineを破棄し、新しいUAで通知なしのbaselineを作り直します。
- MainForm の「状態」列はウィンドウの残余幅を吸収します。固定列のユーザー幅は保存され、狭い場合は水平スクロールします。
- FFmpegのPCMを要求サイズまで読み取り、short read による途切れを解消しました。FFmpegはshell非経由で非表示起動し、検証済みcacheを再利用します。埋め込みFFmpeg archiveそのものは変更していません。

## v1.0.3 の要点

- `MonitorRevision` を監視対象の設定世代として保存し、巡回開始時と保存時で世代を照合します。巡回中に URL / 方式 / Feed / CSS / XPath / 正規表現が変わった取得結果は、baseline・履歴・HTTP cache・通知済み状態へ書き戻さず破棄します。
- スケジュール変更時は旧 `NextDue` を再利用しません。Interval は新間隔から、Daily は次の指定時刻から、無効・手動は `null`、再有効化と監視条件変更は即時確認として再計算します。
- 通知音は開始・完了・失敗・停止を非同期結果で扱います。FFmpeg / decoder / output device / DRM可能性を隠さず報告しつつ、音声だけの失敗で監視・他通知チャネル・通知済み記録を巻き戻しません。MIDI は完了・停止・終了時に MCI device を close します。
- MainForm は × でレイアウト保存後に Dispose され、トレイから再度開くと必要時だけ生成します。監視 scheduler・DB・HTTP client は再生成しません。
- FFmpeg 統合テストは埋め込み archive を一時ディレクトリへ展開する本番同等の経路だけを使い、開発 PC 固定の FFmpeg パスに依存しません。

- 通知音は256件の有界 FIFO queue を単一 worker で処理します。FFmpeg、NAudio、MIDI を同一の直列 session 管理下に置き、容量超過は明示的に失敗・記録し、監視処理を待機させません。
- テスト再生も同じ queue を使用します。「停止」は再生中のテスト要求だけを cancellation し、通知音は止めません。終了時は新規投入を止め、再生中・待機中の要求を安全に完了してから短時間で worker を終了します。
- GUI フォントは10～18ptで永続化され、Ctrl＋プラス／マイナスで変更できます。ホイールは通常のスクロールに使用し、フォントを変更しません。全フォームの再レイアウトを直ちに行います。
## ビルド

Windows 11 x64 と .NET 10 SDK を使用し、`src` を作業ディレクトリにして実行します。配布EXEは自己完結形式で、利用者による.NETランタイム導入は不要です。

```powershell
dotnet restore .\WebSiteMonitor.sln
dotnet build .\WebSiteMonitor.sln -c Release
dotnet test .\WebSiteMonitor.sln -c Release --no-build
dotnet publish .\WebSiteMonitor\WebSiteMonitor.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishTrimmed=false -p:DebugSymbols=false -o .\publish
New-Item -ItemType Directory -Path ..\release -Force
Copy-Item .\publish\WebSiteMonitor.exe ..\release\WebSiteMonitor_v1.1.6.exe
```

## ポータブルデータ

EXE と同じ場所に `data\settings.json`、`data\WebSiteMonitor.db`、`data\logs`、`data\sounds`、`data\cache` を作成します。書き込み不可の場合は AppData へ切り替えず、起動エラーを表示します。ユーザーが新版へ複製した旧DBだけを schema 7 に冪等移行します。既存 Sites / History、未確認通知、4種類の通知設定を保持します。旧スキーマから移行したサイトの更新ダイアログは従来どおりOFF、新規サイトだけONです。

移行前にSQLiteオンラインバックアップを同じ `data` 内の `WebSiteMonitor.db.pre-v1.0.7-日時-識別子.bak` へ保存します。バックアップに失敗した場合は移行を開始しません。旧版へ戻す際の後方互換性は保証せず、アプリ終了後にこの移行前バックアップから復元する方針です。復元先に以前のWAL/SHMを混在させないでください。バックアップには移行後の変更は含まれません。未確認通知は通常の履歴とは別のテーブルで保持し、「閉じる」・×・Esc（Enterはフォーカス中のボタンに従う）による確認時に現在の未確認行だけを削除します。

## 音声形式

MP3 / AAC / M4A / M4B / M4P / ALAC / FLAC / WAV / WMA / OGG / OPUS / AIFF / AMR / AC3 / DTS / APE / WavPack / TTA / TAK / RealAudio / CAF / AU / PCM / MIDI を選択できます。形式・DRM・ネットワーク等により FFmpeg がデコード不能な場合は再生だけが失敗し、監視と他の通知手段は継続します。DRM解除・回避は行いません。通知待機中に decoder / FFmpeg process / MIDI device は常駐しません。

## Windows通知とライセンス

Windows通知は固定AUMID `WebSiteMonitor.App` とユーザー単位の登録を使用します。設定の「Windows通知・スタートメニュー統合を有効にする」で明示的に再有効化できます。About画面には EXE に埋め込んだ第三者ライセンス本文を表示します。依存関係とライセンスは `THIRD_PARTY_NOTICES.md` に記載しています。

JavaScriptレンダリングやWebView2は使用しません。
